## 第 0 层 · 产品定位

- 给自己用的 macOS 语音输入工具：**按住热键说话，松手后纠正过的文字出现在光标处**。
- 菜单栏常驻（不占 Dock），主窗只做配置，日常操作零窗口。
- 个人长期工具：一切可配置、ASR/LLM 可换（不被单一服务商绑架）、数据全在本地。
- 非目标：不做 Windows/移动端；不做多人与云端同步；不做人声克隆、翻译等扩展功能；非商业发布。

## 第 1 层 · 原始需求（已钉死，共 11 条）

1. **语音转文字**——按住热键说话，松开后 ASR 转成文字
2. **模型纠正**——LLM 把转写纠正成正确的书面语
3. **写入光标**——纠正后的文字写到当前光标位置
4. **可重复**——连续说多段
5. **ASR 可换**
6. **LLM 可换**
7. **截图作为纠正的上下文**
8. **记录内容**——原文、纠正结果、音频
9. **历史可查**
10. **可重跑**
11. **浮窗显示对应的内容**

## 第 2 层 · 逐条展开

### 2.1 语音转文字

**行为**
- 按住热键开始录音、松开结束并送识别（hold，默认）；toggle 模式：按一下开始、再按结束
- Esc 中止本段：丢弃，不进识别，浮窗提示
- 可绑多组热键，任一组触发
- 麦克风按优先级列表自动选择，设备热插拔后自动跟上
- 按住过短视为误触忽略；录音超长自动截断、按正常松手收尾
- 录音中浮窗实时显示音量电平；长静音有提醒
- 识别过程中浮窗可实时显示部分文本（引擎支持时）

**结果三形态**
- 正常：得到文字 → 进纠正与交付
- 没听清（无有效语音）：浮窗短提示，不进交付，记一条历史 ⚖️D2
- 识别失败：浮窗报错，本段标记失败（保留音频），不阻塞后续段，可重试

**配置**：触发模式、热键组（通用页）；麦克风优先级、录音时长上限（通用页）；试音按钮（历史页顶栏）
**显示**：浮窗（电平/状态/partial/提示）

⚖️D5 最短录音时长是否为活配置（现状：配置项存在但不生效）

### 2.2 模型纠正

**行为**
- LLM 按 prompt 把转写纠正为书面语；结果经 tool_calls 结构化提交（防模型自由发挥）
- 输入 = ASR 原文 + 词典纠错预处理 +（开启时）屏幕截图
- 纠正可整体关闭；关闭/失败/超时时**不阻塞交付**，降级交付 ⚖️D1（降级内容：ASR 原文还是词典纠错版？）
- LLM 每次调用的请求/响应全量落日志，可查
- 设置页提供"自测"按钮：拿一段样例走完整纠正链路并报告结果

**配置**：纠正开关、LLM 超时（LLM 页/通用页）
**显示**：历史 llm_used 字段、自测结果、LLM 日志目录

### 2.3 写入光标

**行为**（逐级尝试，前一级成功即止）
- 总目标：写进当前光标处；无论如何**文字必须拿得到**（最差进剪贴板）
- 前台是本应用自己的窗口 → 只写剪贴板（防自吞）
- AX 直写目标应用光标处，写后回读校验
- 粘贴优先名单内的应用跳过 AX 直写，直接走可靠粘贴（回执确认）
- 焦点在交付前已变化 → 放弃写入目标应用，仅写剪贴板（防贴错应用）
- clipboard_only 模式：永远只写剪贴板，不尝试写入
- 可靠粘贴：注入 Cmd+V 后以"目标应用读取了剪贴板"为回执确认成功

**选项**
- 交付后追加换行
- 交付后恢复用户原剪贴板内容 ⚖️D3（与"先写剪贴板"现状矛盾，语义待裁决）

**配置**：clipboard_only、恢复剪贴板、追加换行、粘贴优先名单（通用页）
**显示**：浮窗交付确认；历史 delivered 字段（ax 直写/粘贴/仅复制/焦点变化…）

### 2.4 可重复（连续多段）

**行为**
- 转写进行中可再按热键开始下一段（同一时刻只有一段在录音）
- 转写与交付严格按录音顺序（FIFO），后录的不会先交付
- 某段失败不影响其他段
- "清空队列"不丢数据：排队段先进历史（标记取消）再出队
- 失败段保留在队列尾部，可逐个重试或关闭

**显示**：浮窗队列区（最多展示 5 段，含各段状态）

### 2.5 ASR 可换

**行为**
- 多档案管理（名称/类型/base_url/key），同一时刻激活其一，随时切换
- 引擎类型四种：豆包（流式，主力）、智谱（整段上传）、本地网关、OpenAI Realtime ⚖️D9（后者未实测且带收尾缺陷，去留待裁决）
- 内置本地网关：APP 自动拉起子进程、随机端口零配置、探活复用外部实例、退出只收自己的
- API Key 池
- 词典热词自动注入当前引擎（帮 ASR 提前认对专有名词）

**配置**：ASR 页（档案卡、内置引擎卡：模型/VAD/分块/端点/并发等、网关日志实时查看）
**显示**：档案卡状态、网关状态与日志

### 2.6 LLM 可换

**行为**
- 多档案管理（base_url/key/模型/prompt/调用参数），随时切换
- Key 池；模型列表在线拉取
- prompt 可自定义，留空用默认

**配置**：LLM 页
**显示**：档案卡、模型下拉、Markdown 预览

### 2.7 截图作为纠正的上下文

**行为**
- 按下热键时探测活动目标：焦点窗口 → 指针所在窗口 → 指针所在屏，三级回退
- 只截活动目标（窗口或整屏），不截全屏多窗
- 截图失败：纠正照常进行（无图降级，不阻塞）
- 三种模式：off / active_window（默认）/ active_display
- 截图与浮窗定位共用同一次探测结果
- 截图文件保留最近若干张，自动清理；目录可从设置页打开

**配置**：通用页 detect_active_target
**显示**：截图目录入口

### 2.8 记录内容

**行为**
- 每段记录字段：原文、纠正结果、是否用了 LLM、交付方式、引擎、时间、音频路径
- 音频存 wav，按保留策略（保留最近 N 段）自动清理
- 取消段、失败段同样留痕（标记取消/失败），音频与原文保留

### 2.9 历史可查

**行为**
- 历史页：列表 + 详情
- 顶栏切换器（ASR 档案 / LLM 档案 / 麦克风）即选即用——历史页同时是快速换档的地方
- 条目可复制、可重跑、可重转
- 清空需两步确认
- 超出保留上限自动裁剪（先清最旧）

**显示**：主窗历史页

### 2.10 可重跑

**行为**
- 重跑：用保留的音频重新走 识别→纠正→交付 全链路
- 重转：用已有原文重新走 纠正→交付（不重新识别）
- 失败段可重试（浮窗失败条 / 历史页）
- ⚖️D4 成功交付的条目也应可重跑（现状：成功条目音频路径未回填，重跑不可用——按第 1 层第 10 条，这是缺陷）

### 2.11 浮窗显示对应的内容

**行为**
- 显示时机：**按下热键即显示**；转写中/队列非空期间常显（无超时）
- 收起时机：全部交付完成约 350ms 后收起；只剩失败段 2.5s 提示后收起；一次性提示（如"录音太短"）2.5s
- 内容：阶段状态、音量电平、实时回显、队列（≤5 段含各自状态）、失败提示条（重试/关闭按钮）
- 定位：贴近光标/活动目标，屏幕边缘自动翻转；宽度随有无队列切换（480/664px）
- 由后端快照轮询驱动（150ms），不依赖事件推送

⚖️D7 队列变化（重试/清空后）浮窗必须及时反映（现状存在漏刷场景）
